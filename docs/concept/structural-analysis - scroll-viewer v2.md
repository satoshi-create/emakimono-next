# クリステンセン理論構造分析書：絵巻物ビューアー（Emakimono Viewer）

## 1. 歴史的文脈（Evolution Timeline）
このテーマにおける市場進化は、「日本語中心の高精細アーカイブ」から「世界共通の動画的な体験UI」へと価値基準が移る流れとして整理できる。現行構想とコードベースでは、`next-i18next` による日英対応、`Meta.js` による canonical / hreflang、`buildEmakiJsonLd.js` による `VisualArtwork` JSON-LD、`EmakiConteiner.js` による横スクロール自動再生の初回ナッジが、その転換点を具体的に支えている。

- **【フェーズ1】黎明と階層の確立**: 国立文化財機構 ColBase、各美術館・研究機関、British Museum などの公開画像・所蔵情報が、絵巻デジタル公開の基礎を築いた。ここで形成された初期市場は、研究者・学芸員などの Top 層、一般公開コレクションを使う Main 層、そもそも日本語や作法の壁で到達できない Low / 非消費層に分かれる。
- **【フェーズ2】理論の構造化**: 絵巻を「静止画像の保管庫」ではなく「時間的に追う物語体験」とみなす発想が明示化した。さらに IIIF、i18n、構造化 JSON / YAML、JSON-LD などの標準技術が、絵巻を検索・配信・再利用可能なデータとして扱う枠組みを与えた。
- **【フェーズ3】戦略の転換（引き算の導入）**: 既存アーカイブが追求する学術性・高解像度・日本語中心の説明を前提にせず、YouTube 的な再生感覚、横スクロール、自動再生ナッジ、短い説明、シーン共有という「引き算」の導線に寄せる構想が現れた。現行コードでも初回訪問時に右から左へ自動で流し、ユーザーの操作で停止させるロジックが実装されている。
- **【フェーズ4】軌道のクロスオーバー**: 破壊的プロダクトが主流市場に食い込む条件は、単なる実験 UI ではなく、SEO、共有、国際化、モバイル運用を備えた配信基盤になることにある。現行実装では canonical / hreflang、`VisualArtwork` JSON-LD、PWA、Cloudinary 配信、シーン URL 共有の要素がすでに揃い始めている。
- **【フェーズ5】破壊的技術の完成**: 将来的には、絵巻が「日本語で読む閉じたデータベース」から「世界中のユーザーが自動再生で入り、止めて拡大し、シーン単位で共有し、必要に応じて再利用する文化インフラ」へ変わる。完全な置換ではなく、一次ソースを保つ既存機関を上流に残したまま、下流の体験 OS を置き換える形で進む可能性が高い。

## 2. 評価軸（分子と分母）

- **分子（持続的イノベーション軸 / 既存巨頭の競争スペック）**:
  - 原寸級に近い高精細画像
  - 日本語での学術的注釈・厳密な記述
  - 専門家向けの比較・参照・所蔵情報の充実
  - 正確性・保存性・一次資料性
- **分母（破壊的イノベーション軸 / 破壊者の引き算要素）**:
  - YouTube 的に直感的な操作
  - 右から左へ流れることで作法を先に理解させる自動再生
  - 日英対応と短い説明で参入障壁を下げること
  - シーン URL 共有や軽量配信による拡散のしやすさ
  - 現行 URL / SEO 資産を保ったまま段階的に改善できること

このテーマの本質は、「より多く説明すること」ではなく、「最初の理解コストをどこまで下げられるか」にある。既存勢力は分子を磨くほど強くなるが、非消費層にとっては分母の改善の方が価値になる。

## 3. オーバーシュート（性能過剰）の特定

- **High（最上位層）**: 研究者・学芸員・専門家にとっては、IIIF Viewer、詳細メタデータ、日本語中心の精密な解説、高解像度原本参照が重要である。一方で、一般ユーザーにはその多くが過剰で、最初の数秒では価値として認識されにくい。
- **Main（主流層）**: 美術館サイトや一般的なデジタルコレクション利用者にとっては、「画像が見える」「最低限の説明がある」「拡大できる」程度で満足する場合が多い。ここでは複雑な UI や説明過多が離脱要因になりうる。
- **Low（ローエンド・新市場層）**: 海外ライト層、SNS 由来流入、授業や会話の中で偶然触れるユーザーにとっての閾値は、「スマホで1秒で開ける」「なんとなく右から左に流れて物語として感じ取れる」「止めて共有できる」で十分である。ここでは Good Enough が最重要であり、これが新市場の入り口になる。

## 4. 構造的マッピング（3層構造分析）

### ［Top Layer］製品・用途
- **インカンベント製品**: 日本語中心のデジタルアーカイブ、IIIF Viewer、公式コレクションページ。価値は高いが、非専門家には重く見える。
- **ディスラプター製品**: Emakimono Viewer。横スクロール、再生感覚、共有しやすさ、モバイルでも使える導線で、「鑑賞の開始コスト」を下げる。
- **主流市場への浸透プロセス**: まず海外ライト層や SNS 流入で Good Enough な導入体験を作り、その後、教育利用・研究者の紹介・多言語共有を通じて主流層へにじみ出る。現行コードの `Meta.js`、`buildEmakiJsonLd.js`、シーン共有機能は、この浸透に必要な発見性と拡散性を支えている。

### ［Middle Layer］技術・機構
- **核心的技術**:
  - Next.js Pages Router による静的ページ生成
  - `next-i18next` による日英ローカライズ
  - `Meta.js` の canonical / hreflang
  - `buildEmakiJsonLd.js` の `VisualArtwork` JSON-LD
  - `EmakiConteiner.js` の自動スクロール / 再生モード / ハッシュ付きシーン遷移
  - Cloudinary 配信と `next/image`
- **簡素化の工夫**:
  - 初回訪問時のみ自動再生で操作説明を省略する
  - ユーザー操作で即停止できるようにする
  - ハッシュ付き URL のときは自動再生をスキップし、共有意図を優先する
  - SEO を保ちながら小さく改善できる Pages Router 構成を残す

### ［Bottom Layer］インフラ・哲学・バリューネットワーク
- **基礎理論/物理法則**: 破壊的イノベーション理論、ジョブ理論、認知慣習（メンタルモデル）、Web の静的配信と画像最適化、構造化データによる検索理解。
- **経営哲学/戦略思想**: 「学術的完全性を入口で要求しない」「機能追加ではなく最初の体験コストを削る」「既存 SEO 資産を壊さず、段階的に前進する」という思想。
- **旧バリューネットワーク（解雇されたネットワーク）**: 日本語中心の閉じた説明、専門家前提の評価基準、重い閲覧導線、一次資料の精密さを入口体験にまで持ち込む設計。
- **新バリューネットワーク（雇用されたネットワーク）**: YouTube 的 UI 慣習、グローバル検索、SNS 共有、Cloudinary の画像配信、PWA、OSS/AI を含む国際的な Web 開発エコシステム。

## 5. ジョブ理論 (JTBD)

- **雇用したジョブ (Hire)**: 「海外の美術ファン、学生、SNS から流入したユーザーが、日本語や専門作法を知らなくても、スマホで開いてすぐに絵巻の物語感をつかみたい」という状況で、Emakimono Viewer を雇用する。
- **解雇したジョブ (Fire)**: 「重いデジタルアーカイブを開き、日本語の説明を読み解き、どこから見始めればよいか分からないまま離脱する」という従来の手間を解雇する。さらに、「共有したい場面があっても URL や画像として切り出しにくい」という不便も解雇対象になる。

## 6. CARDS（実在する重要銘柄・企業の特定）

### 上場企業・有力企業リスト
1. **Alphabet (GOOGL)**:
   - **市場での役割**: インカンベントかつ参照すべき UI 規範
   - **分析**: YouTube はこの構想における最重要メンタルモデルの供給源である。Emakimono Viewer 自体は YouTube の競合ではないが、ユーザーがすでに学習済みの再生・シーク・視聴の慣習を借りることで参入障壁を下げる点で、Alphabet のプロダクト設計は事実上の基準面になっている。
2. **Cloudinary (private, proxy: Cloudflare NET / Fastly FSLY)**:
   - **市場での役割**: ディスラプター側インフラ
   - **分析**: 現行コードは Cloudinary 配信を前提にしており、軽量な画像配信・変換・グローバル最適化はローエンド浸透に直結する。Cloudinary は未上場のため、画像 CDN・エッジ配信の上場 proxy として Cloudflare や Fastly が比較対象になる。
3. **Vercel (private, proxy: Cloudflare NET)**:
   - **市場での役割**: ディスラプター側プラットフォーム
   - **分析**: Next.js / Pages Router / PWA / 静的配信という現行アーキテクチャの中心にいる。未上場だが、Web エッジ配信と開発基盤の観点では Cloudflare が近い公開 proxy として参照できる。
4. **Microsoft (MSFT)**:
   - **市場での役割**: 拡張者
   - **分析**: GitHub と OSS エコシステムは、段階的アップグレード、共有、AI 活用、国際的な開発フローを支える。Emakimono Viewer が単独プロダクトではなく、OSS や AI 連携を含む文化インフラへ広がる場合、その開発基盤面での影響力が大きい。
5. **Adobe (ADBE)**:
   - **市場での役割**: インカンベント側の高機能ワークフロー代表
   - **分析**: 高度な制作・アセット管理・編集ワークフローは強力だが、ローエンド鑑賞体験の入口としては重い。Emakimono Viewer は Adobe 的な高機能制作を置き換えるのではなく、その手前で「まず見る・感じる・共有する」を奪う位置に立つ。

## 7. GLOSSARY（重要テーマ用語集）

1. **IIIF (International Image Interoperability Framework)**:
   - **該当レイヤー**: 技術 ／ 哲学インフラ
   - **テーマ文脈を踏まえた解説**: 美術画像とメタデータを相互運用可能にする国際的な枠組み。絵巻を一機関内の閉じた画像集合ではなく、横断的に扱えるデータへ変える基盤になる。
2. **Hreflang**:
   - **該当レイヤー**: 製品 ／ 技術
   - **テーマ文脈を踏まえた解説**: 言語別 URL の関係を検索エンジンに伝える仕組み。現行 `Meta.js` では `ja` / `en` と `x-default` を出力しており、グローバル展開時の SEO 土台として重要である。
3. **VisualArtwork JSON-LD**:
   - **該当レイヤー**: 技術
   - **テーマ文脈を踏まえた解説**: 絵巻ページを単なる HTML ではなく、美術作品ページとして検索エンジンに理解させる構造化データ。現行 `buildEmakiJsonLd.js` に実装されている。
4. **RTL (Right-to-Left) Narrative Flow**:
   - **該当レイヤー**: 製品
   - **テーマ文脈を踏まえた解説**: 絵巻を右から左へ追う体験のこと。説明文で教えるのではなく、自動再生や UI の流れで身体的に理解させることがこの構想の中核である。
5. **PWA (Progressive Web App)**:
   - **該当レイヤー**: 技術 ／ 哲学インフラ
   - **テーマ文脈を踏まえた解説**: Web サイトをアプリ的に扱う仕組み。現行 `next.config.js` では `next-pwa` を用いており、将来の ambient 利用や繰り返し接触の基盤となる。

## 9. COMBINATION（新結合分析）

### 新結合ケース1
- **キャッチフレーズ（要素A × 要素B）**: YouTube 的再生 UI × 絵巻の横スクロール鑑賞
- **新結合の分類**: 新製品 / 新市場
- **結合された既存要素**:
  1. 世界中のユーザーが学習済みの動画プレイヤーの操作慣習
  2. 右から左に時間的に追う絵巻という既存文化形式
- **破壊を可能にした理由**: どちらも単独では新しくないが、「絵巻を動画のように触る」という組み合わせによって、作法学習を不要にし、新市場層の入口障壁を劇的に下げるから。
- **もたらされた成果（製品・ノード）**: 自動再生ナッジを備えた Emakimono Viewer、将来的なシークバー型 UI、ローエンド鑑賞導線。

### 新結合ケース2
- **キャッチフレーズ（要素A × 要素B）**: 構造化 SEO × 多言語静的配信
- **新結合の分類**: 新生産方式 / 新市場
- **結合された既存要素**:
  1. canonical / hreflang / JSON-LD といった検索理解の標準技術
  2. `next-i18next` と静的生成による日英ページ配信
- **破壊を可能にした理由**: 文化コンテンツは優れていても、検索・言語・共有で見つからなければ非消費のまま残る。SEO と多言語配信を組み合わせることで、「存在しているのに到達できない」を減らし、文化資産を新市場へ露出できる。
- **もたらされた成果（製品・ノード）**: `Meta.js`、`buildEmakiJsonLd.js`、日英の静的絵巻ページ群。

### 新結合ケース3
- **キャッチフレーズ（要素A × 要素B）**: 一次資料アーカイブ × 軽量画像配信インフラ
- **新結合の分類**: 新生産方式 / 新市場
- **結合された既存要素**:
  1. ColBase や各館が保持する一次資料・高精細画像
  2. Cloudinary、PWA、`next/image` による軽量配信と最適化
- **破壊を可能にした理由**: 一次資料の価値を保ちながら、閲覧導線だけを軽量化できる。これにより、元の重いアーカイブを壊さずに、手前の体験層だけを刷新できる。
- **もたらされた成果（製品・ノード）**: モバイル前提の絵巻ページ、共有されやすいシーン体験、将来の ambient 利用基盤。

## 10. 分析の論理整合性チェック（品質管理）
1. [OK] 分母（破壊軸）で挙げた「引き算の要素」は、JTBD の「重い日本語中心アーカイブを開いて離脱する手間の解雇」と一致している。
2. [OK] 特定したディスラプター企業・周辺企業は、タイムラインの主役である YouTube 的 UI、画像配信、Web 配信基盤と整合している。
3. [OK] 新結合分析で組み合わせた要素は、Middle 層の簡素化（自動再生、SEO、多言語、軽量配信）と Bottom 層の思想（参入障壁を下げる）に寄与している。
