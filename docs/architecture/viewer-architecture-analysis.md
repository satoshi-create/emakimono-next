# クリステンセン理論構造分析書：[絵巻物ビューアー]

## 1. 歴史的文脈（Evolution Timeline）

* **[フェーズ1：黎明期] (Bottom Layer)**: `デジタル・アーカイブの出現`。美術館や研究機関が、高精細データと釈文の提供を開始。学術利用という「Bottom」からの発展。
* **[フェーズ2：持続的深化] (Top Layer)**: `オーバーシューティングの時代`。既存機関が更なる高画質、多機能ビューアを競う。主流市場顧客（研究者）の要求に対し性能が過剰供給される。
* **[フェーズ3：破壊的芽生え] (戦略の転換)**: `Emakimono Viewerの登場`。解説や重厚なUIを「引き算」し、「横スクロールの没入感」に特化。これがローエンドからの参入となる。
* **[フェーズ4：軌道のクロスオーバー] (クロスオーバー)**: `データ基盤（ハブ）化への転換`。UIのシンプルさを維持しつつ、IIIF等の標準規格を統合し、AIやエンジニアが再利用可能なインフラへと進化する瞬間。
* **[フェーズ5：破壊の完成] (破壊的技術の完成)**: `文化インフラの民主化`。既存のハイエンドビューアが「重すぎて使えない」とされ、当プラットフォームが標準的な閲覧・利用OSとなる。

## 2. 評価軸（分子と分母）

* **分子（持続的イノベーション軸）**: 学術的な網羅性、釈文の深度、ビューアの表示機能（拡大・計測等）、画像精細度の閾値。
* **分母（破壊的イノベーション軸）**: インタラクティブな再構築の容易さ、データ再利用コスト、環境構築の爆速性、没入感（スクロール体験）。

## 3. オーバーシュート（性能過剰）の特定

* **High (y=90)**: 研究機関が提供する高度なWeb IIIF Viewer。一般層には不要な機能が多すぎる。
* **Main (y=60)**: 一般的な画像閲覧サイト。
* **Low (y=25)**: Emakimono Viewerが提供する「物語を一瞬で体験する」ための必要十分な体験。

## 4. 構造的マッピング (Universal Matrix)

### Top Layer: 製品・用途

* **[インカンベント製品]**: 既存の博物館デジタルアーカイブ（高機能だが、使いこなせない高嶺の花）。
* **[ディスラプター製品]**: Emakimono Viewer（ローエンドから入り、AI・OSS活用で利便性を爆速化）。
* **[次世代への継承]**: 既存データ資産を飲み込み、ユーザー主導で再文脈化する「物語プラットフォーム」。

### Middle Layer: 技術・機構

* **[核心的技術]**: Next.js 15 (App Router) + IIIFパーサー。
* **[簡素化の工夫]**: コンテンツのパケット方式（断片表示）による低負荷ロード、JSONメタデータによる疎結合。

### Bottom Layer: インフラ・哲学

* **[基礎理論]**: 破壊的イノベーション理論、Jobs-to-be-Done (JTBD)。
* **[経営哲学]**: 「閲覧」から「編集・共有」への体験軸の転換。
* **[バリューネットワーク]**: 著作権管理組織や専門家だけでなく、AIエンジニアやコントリビューターを取り込んだエコシステム。

## 5. ジョブ理論 (JTBD)

* **雇用したジョブ (Hire)**:
「自分の日常やAIプロジェクトなどの『特定の状況』において、専門知識（お作法）なしで、絵巻物の物語を瞬時に把握し、自分のコンテキスト（切り抜き・タグ付け）を付与して物語を『再利用』したい。」
* **解雇したジョブ (Fire)**:
「高価で複雑なハイエンドビューアを使うために支払っていた学習コスト、リンク切れ（404）による機会損失、そして『鑑賞者になることしか許されない』という受動的な体験。」
